# PCB RouteLab 发布修补长目标

范围：从已有 DeepSeek Harness PCB 研究提取稳定可复用功能，保留原算法；独立桌面源码包，通过离线验收后上传独立 GitHub 仓库。名称为 PCB RouteLab，区别于 PCB TraceMend。

## 阶段与通过条件
1. 来源和发布清单：记录自有/第三方代码来源、许可、哈希；仅复制显式选定文件。原研究和冻结证据只读；不复制 API 配置、原始响应、用户板、虚拟环境、大归档。
2. 可迁移运行：统一 CLI、独立工作目录、可配置 KiCad/路由 Python、固定依赖和 Rust 源码构建；移除作者电脑绝对路径。原生路由、Harness 诊断工具、固定联合计划、拥塞表达式分开入口。
3. 交付保护：输入检查，原板/规则/布局保护，独立候选验收，不合格不导出；超时/取消/错误/安全未完成/成功明确区分。模型联网默认禁用，显式启用且预算有限。
4. 离线验收：干净环境从发布包安装和构建；示例原生 KiCad 检查、固定动作/计划和策略回放；模型协议以本地模拟测试，不调用外部模型 API。负向验证规则变更、损坏连接、未知输入、超时及取消。
5. 开源整理：中英文说明、安装/使用/故障排查、支持边界、结果说明、许可证、精简证据、CI。归档历史结果与公开代码修补分开。
6. 发布：文件及秘密扫描、逐项交付审计通过后上传 GitHub；远端核对与 CI 结果记录。

## 停止与边界
不做算法扩展、新数据集或性能研究。不调用模型 API，包括验证密钥；若确实只能在线验证，先报告具体缺口并询问用户。依赖下载和 GitHub 上传不属于模型调用。保护失效先修复，不能绕过检查。单个明确问题最多三轮有依据修补，失败保留并继续独立必需项；不能以文档改名代替功能验收。只有全部必需交付通过，或用户停止，或真实外部阻塞且无独立工作可推进时结束。发布前不改旧仓库，不上传历史用户板。既有实验冻结代码不改写；公开适配差异单独记录。
